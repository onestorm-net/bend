# Anti-patterns to avoid

Lessons-from-pain captured outside SKILL.md so they're loaded once on demand, not every invocation. Mechanics that SKILL.md already states as rules (how to use `AskUserQuestion`, how short to keep inter-round text, pushing back on vague answers) are not repeated here; this file is for the failures those rules don't describe.

- **Skipping the Kendo board check**: issues and epics may already define the scope
- **Skipping the shared code audit**: don't plan a second VarInt, string or array reader next to `ProtocolUtil`. Two readers for the same encoding is how the frame decoder and the encoder disagreed on width
- **Writing "add tests" without behavioral detail**: every test in the plan must describe an observable outcome (bytes in, packet or exception out; peer goes silent, disconnect with type 3), not an implementation check
- **Generic questions** that could apply to any project: ground every question in the codebase and the spec
- **Asking about low-level implementation details**: "Should this be a `for` loop or a stream?" is the developer's call during implementation
- **Self-reviewing your own conventions usage**: you will rationalize your choices. The `plan-reviewer` agent exists specifically to catch what you won't. Never skip Phase 5.
- **Presenting your recommendation as settled**: the interview mode is "I'd pick X because Y: agree, or pick another?", not "we're using X, right?". A stance the developer can't cheaply reject is worse than no stance. (Leading *with* a recommendation is the required mode; what's forbidden is foreclosing the alternative.)
- **Designing from first principles instead of from the codebase and CLAUDE.md**: if packets are Lombok classes implementing `Packet`, your plan's packet is too. If wire-input failures throw `ProtocolException`, yours do too. You don't get to invent a "better" approach unless the developer explicitly asks for a deviation. The ADRs in `docs/decisions/` record decisions together with the alternatives that were considered and declined, in their Rejected sections (canonical VarInt encoding in 0003, a `Protocol` epic in 0023, auto-`final` on locals in 0015): re-proposing a declined alternative without new evidence is re-litigating, and the ADRs exist to stop exactly that.
- **Adding a "defensive" check the code can't reach**: Bend deletes unreachable checks instead of keeping them as future-proofing (CLAUDE.md § Testing / coverage). A planned guard needs an input that reaches it and a test that feeds it that input.
- **Burying design decisions in the plan body**: the developer should not have to read 400 lines to find that you chose a `ConcurrentHashMap` registry over event-loop confinement. Key Design Decisions go in the table at the top. If a structural choice isn't in that table, it's invisible to review.

## Calibration: the fractional-rank plan (2026-05): confidently-wrong claims cost three reviewer rounds

This calibration comes from the web project these skills were first written for; the failure categories carry over to Bend unchanged. A plan for board ordering needed R1 → R2 → R3 reviewer cycles to converge. Each round caught a different category of confidently-wrong-but-unverified claim. The plan logic was structurally sound from R1; the problems were at the citation layer. Phase 1.4 ("Pre-flight verification") was added in response. Only the first two buckets below are resolved mechanically by `scripts/verify-citations.sh`: it answers "does this exist", which is all those two needed. The third needs a framework source citation. The fourth needs the full grep-and-inspect pass and no script can shortcut it: knowing a symbol exists says nothing about whether you found all of its callsites, and callsite coverage is the entire bucket.

- **Phantom paths.** Cited a helper in a directory that did not exist; the sibling helpers lived elsewhere. Cited an event class in a package that didn't exist. Both citations would have been one `ls` away. **Lesson:** if you say "the closest analog is X siblings", `ls` the directory holding the siblings first. In Bend terms: `protocol/src/main/java/net/onestorm/bend/protocol/` has `codec/`, `endpoint/`, `exception/`, `packet/`, `util/`; a plan citing `.../protocol/handler/` is citing nothing.

- **Fabricated precedent.** Cited an endpoint as the precedent for a convention. The class behind it existed; the endpoint did not. The convention claim was right; the precedent citation was invented. **Lesson:** "this follows the X precedent" requires grep-confirming X exists. The convention may be real and the named example may still be invented. `ProtocolUtil#readVarLong` sounds plausible and does not exist.

- **Wrong framework behavioural claim.** Claimed the framework's transaction retry covered a unique-constraint violation. Verified false against the framework source in R2: it only retried on a short list of deadlock errors. The mechanism the entire concurrency story depended on did not exist. **Lesson:** any claim of the form "Netty does X" needs a source citation (class and method at the pinned release tag) or an explicit downgrade to "verify at implementation." ADR 0009's Context shows the right shape: the claim that `ByteToMessageDecoder` never calls `decode()` with an empty buffer was traced to its `callDecode()` loop before a check was deleted on the strength of it.

- **Removal-blast-radius miss.** Planned to delete an endpoint based on two callsites. A third callsite in an unrelated bulk flow used the same payload shape. The plan as written would not have compiled in PR1. **Lesson:** before scoping out the deletion of any symbol, `grep -rn <symbol>` across every module's `src/`, the spec and `CLAUDE.md`, and inspect *every* hit, not just the ones from the obvious feature path.

The combined cost: three reviewer rounds, ~400 LOC of rewritten DECISIONS.md/PLAN.md, two BLOCKERs, and ~25 minutes of agent runtime. The combined cost of running Phase 1.4 up-front: under 10 minutes of grep.
